Backend

Backend dibangun dengan Express.js + SQLite (better-sqlite3). Semua route API berada di server.js dan modul pendukung.

  • Auth & Session: /api/login, /api/logout, /api/me berbasis express-session.
  • RBAC: middleware checkRole([...]), role: superadmin, admin, pendaftaran, dokter.
  • Maintenance: maintenanceGuard memblokir akses non-admin saat mode on.
  • CRUD: patients, icd10, encounters, config, stats.
  • Settings: tabel settings, endpoint /api/plugins/settings (app name, base URL endpoint, toggle). Jika endpoint aktif, source of truth dari endpoint; jika fetch gagal tampil popup "Data belum tersedia".
  • Database: schema di database/schema.sql, migrasi di database/migrate.js.
  • Modul API: /api/plugins/* (superadmin only untuk manajemen modul opsional).
  • Module Manager: memindai folder modules/, auto-aktivasi modul core, migrasi & rollback.
npm start          # jalankan server
npm test           # smoke test
node database/migrate.js

Frontend

SPA vanilla JS + Tailwind CSS (CDN). Entry: public/index.html dan public/js/app.js.

  • Layout: desktop sidebar + mobile bottom nav.
  • Routing: fungsi switchTab(tab) merender view ke #viewContainer.
  • View: setiap menu bottom nav adalah modul (home, pasien, icd, daftar, akun, modular, dokumentasi, plugin:).
  • Module Host: renderModule() memanggil Module_.render().
  • Builder Pattern: ModuleBuilder untuk menyusun fungsi, screen, dan add-on modul.
  • Responsive: tabel (desktop) + kartu vertikal (mobile) untuk data list.
  • Keamanan UI: superadmin hanya melihat panel modular & dokumentasi.

Ikon menu desktop menggunakan SVG (Heroicons outline) untuk tampilan modern.

RBAC (Role-Based Access Control)

Sistem menggunakan role: superadmin, admin, pendaftaran, dokter. Middleware checkRole([...]) membatasi akses endpoint.

  • superadmin: akses penuh (bypass semua role check).
  • admin: kelola pasien, ICD, kunjungan, config, plugin (kecuali delete core).
  • pendaftaran: daftar pasien & kunjungan.
  • dokter: periksa & diagnosa kunjungan.
  • Maintenance: saat mode on, hanya admin/superadmin yang bisa akses.
  • Masking: NIK dimasking untuk non-admin.
tampilkanPopup(pesan, tipe)

Popup alert reusable (toast/modal) dengan parameter pesan dan tipe dialog.

Masalah yang dipecahkan: alert() bawaan browser tidak konsisten dan tidak bisa dikustomisasi. Helper ini menyediakan popup dengan tipe info/success/warning/error/confirm.

Contoh kasus:

  • Validasi gagal → tampilkanPopup('NIK harus 16 digit', 'error').
  • Konfirmasi hapus → const ok = await tampilkanPopup('Hapus data?', 'confirm').

Contoh penggunaan:

tampilkanPopup('Data berhasil disimpan', 'success');
tampilkanPopup('Terjadi kesalahan', 'error');

const ok = await tampilkanPopup('Hapus data ini?', 'confirm');
if (ok) { /* hapus */ }

Contoh Koding

function checkRole(allowedRoles) {
  return (req, res, next) => {
    if (!req.session || !req.session.user) return res.status(401).json({ error: 'Sesi berakhir.' });
    const role = req.session.user.role;
    if (role === 'superadmin' || allowedRoles.includes(role)) return next();
    return res.status(403).json({ error: 'Akses Ditolak.' });
  };
}

// Penggunaan di route
app.post('/api/icd10', requireAuth, checkRole(['admin']), handler);

Sistem Modular

Hanya Home yang merupakan modul core. Semua modul lain adalah plugin modul. Plugin dapat mendaftar ke bottom menu, tetapi default nonaktif. Untuk menampilkan di bottom menu, aktifkan melalui pengaturan Tampil Menu (maksimal 4 menu). Modul berada di folder modules//.

  • Discovery: core memindai folder modules/ saat boot & tombol Scan.
  • Tampil Menu: maksimal 4 plugin modul aktif di bottom nav; popup warning jika melebihi.
  • Lifecycle: inactive → active (migrasi + register) → inactive (deactivate) → delete.
  • Hook: action & filter ala WordPress.
  • Rollback: aktivasi gagal otomatis di-rollback.
  • Hooks/Events (Observer): modul mendeklarasikan event (before_start, sebelum_simpan, dll.); add-on dapat subscribe via ctx.on().
  • Menu Add Ons: tabel modul aktif + hook/event yang disediakan (informasi). Add Ons adalah core dan menunya muncul di bawah Modular, hanya superadmin.
  • Panel: khusus superadmin (tab Modular).

Contoh Membuat Modul Sederhana

modules/hello-world/module.json
{
  "name": "Hello World",
  "slug": "hello-world",
  "version": "1.0.0",
  "description": "Modul contoh",
  "author": "Dev",
  "main": "server.js",

modules/hello-world/server.js
module.exports = function register(ctx) {
  ctx.registerRoute('GET', '/', (req, res) => {
    res.json({ message: 'Halo dari modul!' });
  });
  ctx.registerMenu({ label: 'Hello', icon: '👋', order: 90 });
  ctx.logger.info('hello-world registered');
};

modules/hello-world/client.js
(function () {
  async function api(url, opts) {
    const res = await fetch(url, Object.assign({ headers: { 'Content-Type': 'application/json' } }, opts || {}));
    const data = await res.json().catch(() => ({}));
    if (!res.ok) throw new Error(data.error || ('HTTP ' + res.status));
    return data;
  }
  function render(container) {
    container.innerHTML = '
Memuat...
';
    api('/api/plugins/hello-world')
      .then(d => { container.innerHTML = '
' + (d.message || 'OK') + '
'; })
      .catch(e => { container.innerHTML = '
' + e.message + '
'; });
  }
  window.Module_hello_world = { render };
})();

Add Ons (Hook/Event)

Modul Add Ons adalah core dan menunya muncul di bawah Modular (khusus superadmin). Halaman ini menampilkan tabel modul aktif beserta hook/event yang disediakan, sehingga add-on dapat mengetahui trigger yang bisa di-subscribe.

  • Observer Pattern: modul mendeklarasikan event; add-on subscribe via ctx.on().
  • Deklarasi: manifest events atau ctx.registerEvent(name, desc).
  • Picu: ctx.emit(eventName, payload) memanggil semua subscriber.
  • Info: Menu Add Ons hanya menampilkan informasi (read-only).

Contoh Koding

// Modul A (mis. pasien) mendeklarasikan event
ctx.registerEvent('sebelum_simpan', 'Sebelum data pasien disimpan');

// Modul A memicu event
ctx.emit('pasien.sebelum_simpan', { id: 123, nama: 'Dewi' });

// Add-on B subscribe
ctx.on('pasien.sebelum_simpan', (payload) => {
  console.log('Add-on menerima:', payload);
});

// Manifest modul A
// "events": [{ "name": "sebelum_simpan", "description": "Sebelum data pasien disimpan" }]

SDK Plugin

Lihat file sdk.md / docs/sdk.md untuk panduan lengkap. Modul disusun dengan Builder Pattern (fungsi, screen, add-on). Ringkasan:

// Deklarasi event di manifest: "events": [{"name":"sebelum_simpan","description":"..."}]

// Modul A menyediakan event
ctx.registerEvent('sebelum_simpan', 'Sebelum data disimpan');
ctx.emit('sebelum_simpan', { id: 123 });

// Add-on B subscribe
ctx.on('modulA.sebelum_simpan', (payload) => { /* ... */ });

// Builder + add-on
const mod = new ModuleBuilder('home')
  .screen('main', (vc) => renderHome(vc))
  .addon('welcome-banner', (m) => { /* wrap render */ })
  .build();
window.Module_home = mod;

Helper Function (Fase 1)

Toolkit helper reusable di folder helpers/ untuk mempercepat pengembangan aplikasi rekam medis.

  • Validasi: validasiNIK, sanitizeInput, validasiICD.
  • Format: hitungUmur, formatTanggalIndo, labelStatusKunjungan.
  • Keamanan: maskingNIK, maskingTelepon, cekRole, hashSensitive.
  • Data & API: generateNoRM, buildPagination, formatResponse.
  • Audit: auditLog(db, userId, aksi, entitas, id, detail) + tabel audit_logs.

Semua helper dibuat pure function (kecuali auditLog yang menerima db) agar mudah di-unit-test.

validasiNIK(nik)

Validasi NIK 16 digit (angka, tidak semua nol).

Masalah yang dipecahkan: Input NIK dari user sering tidak konsisten (kurang digit, ada huruf, atau semua nol). Validasi ini memastikan NIK memenuhi format dasar sebelum disimpan ke database, mencegah data pasien tidak valid.

Contoh kasus:

  • NIK "3507123456780001" (16 digit) → valid.
  • NIK "123" (kurang digit) → tidak valid.
  • NIK "350712345678000a" (ada huruf) → tidak valid.
  • NIK "0000000000000000" (semua nol) → tidak valid.

Contoh penggunaan:

const { validasiNIK } = require('./helpers/validasi');

// Di route POST /api/patients
if (!validasiNIK(nik)) {
  return res.status(400).json({ error: 'NIK harus 16 digit angka.' });
}

// Contoh
console.log(validasiNIK('3507123456780001')); // true
console.log(validasiNIK('123')); // false
console.log(validasiNIK('350712345678000a')); // false
sanitizeInput(str)

Trim dan hapus tag HTML dari input.

Masalah yang dipecahkan: Input dari user dapat mengandung spasi berlebih atau tag HTML yang berpotensi XSS. Helper ini membersihkan input sebelum diproses/disimpan.

Contoh kasus:

  • Input " Halo " → "Halo".
  • Input " " (spasi) → "".

Contoh penggunaan:

const { sanitizeInput } = require('./helpers/validasi');

const nama = sanitizeInput(req.body.nama_lengkap);
if (!nama) return res.status(400).json({ error: 'Nama wajib diisi.' });

console.log(sanitizeInput('  Halo  ')); // "Halo"
validasiICD(code)

Validasi format kode ICD-10 sederhana (A00 atau A00.0).

Masalah yang dipecahkan: Kode ICD yang dimasukkan admin bisa salah format (tanpa huruf/angka yang benar), sehingga data diagnosa tidak konsisten. Helper ini memastikan format dasar ICD-10.

Contoh kasus:

  • "J02.9" → valid.
  • "A00" → valid.
  • "123" → tidak valid.
  • "J0" → tidak valid.

Contoh penggunaan:

const { validasiICD } = require('./helpers/validasi');

if (!validasiICD(code)) {
  return res.status(400).json({ error: 'Kode ICD-10 tidak valid.' });
}

console.log(validasiICD('J02.9')); // true
console.log(validasiICD('123')); // false
hitungUmur(tanggalLahir)

Hitung umur dalam tahun dan bulan.

Masalah yang dipecahkan: Umur pasien sering dihitung manual dan tidak konsisten (tahun saja vs tahun+bulan). Helper ini menghitung umur akurat berdasarkan tanggal lahir.

Contoh kasus:

  • Lahir 1995-05-14, hari ini 2026-11-04 → 31 tahun, 5 bulan.
  • Lahir hari ini → 0 tahun, 0 bulan.

Contoh penggunaan:

const { hitungUmur } = require('./helpers/format');

const umur = hitungUmur(pasien.tanggal_lahir);
console.log(umur); // { tahun: 31, bulan: 5 }

// Tampilkan di UI
const label = umur.tahun + ' th ' + umur.bulan + ' bl';
formatTanggalIndo(date)

Format tanggal ke "14 Mei 1995".

Masalah yang dipecahkan: Tanggal dari database (ISO) tidak nyaman dibaca user. Helper ini memformat ke Bahasa Indonesia.

Contoh kasus:

  • "1995-05-14" → "14 Mei 1995".
  • "2026-11-04" → "4 November 2026".

Contoh penggunaan:

const { formatTanggalIndo } = require('./helpers/format');

const tgl = formatTanggalIndo(pasien.tanggal_lahir);
console.log(tgl); // "14 Mei 1995"
labelStatusKunjungan(status)

Label + warna status kunjungan.

Masalah yang dipecahkan: Status kunjungan (Pemeriksaan/Selesai/Dirujuk) perlu ditampilkan dengan label dan warna yang konsisten di UI.

Contoh kasus:

  • "Selesai" → { label: "Selesai", color: "green" }.
  • "Dirujuk" → { label: "Dirujuk", color: "red" }.

Contoh penggunaan:

const { labelStatusKunjungan } = require('./helpers/format');

const st = labelStatusKunjungan(encounter.status);
// st.label, st.color
maskingNIK(nik)

Masking NIK (4 digit awal + 12 bintang).

Masalah yang dipecahkan: NIK adalah data sensitif. Menampilkan NIK penuh ke role non-admin berisiko privasi. Helper ini menyamarkan sebagian NIK.

Contoh kasus:

  • "3507123456780001" → "3507************".
  • NIK tidak 16 digit → dikembalikan apa adanya.

Contoh penggunaan:

const { maskingNIK } = require('./helpers/keamanan');

// Di GET /api/patients
const nik = role === 'admin' ? r.nik : maskingNIK(r.nik);
maskingTelepon(no)

Masking nomor telepon.

Masalah yang dipecahkan: Nomor telepon pasien juga sensitif. Masking membantu privasi di tampilan list.

Contoh kasus:

  • "081234567890" → "0812****90".

Contoh penggunaan:

const { maskingTelepon } = require('./helpers/keamanan');

const tampil = maskingTelepon(pasien.telepon);
cekRole(user, roles)

Cek apakah user memiliki salah satu role.

Masalah yang dipecahkan: RBAC tersebar di banyak route. Helper ini menyederhanakan pengecekan role dan konsisten (superadmin selalu lolos).

Contoh kasus:

  • user role admin, roles ['admin','dokter'] → true.
  • user role dokter, roles ['admin'] → false.

Contoh penggunaan:

const { cekRole } = require('./helpers/keamanan');

if (!cekRole(req.session.user, ['admin','dokter'])) {
  return res.status(403).json({ error: 'Akses ditolak.' });
}
hashSensitive(value)

Hash SHA-256 untuk data sensitif (privasi).

Masalah yang dipecahkan: Untuk analitik/audit, kadang perlu menyimpan identitas tanpa menyimpan data asli. Hash membantu privasi.

Contoh kasus:

  • Hash NIK sebelum disimpan di log analitik.

Contoh penggunaan:

const { hashSensitive } = require('./helpers/keamanan');

const nikHash = hashSensitive(pasien.nik);
generateNoRM(lastId)

Generate No RM dari id terakhir.

Masalah yang dipecahkan: No RM harus konsisten dan unik. Helper ini membuat No RM dari id terakhir agar tidak bentrok.

Contoh kasus:

  • lastId 2 → "RM-000103".
  • lastId 0 → "RM-000101".

Contoh penggunaan:

const { generateNoRM } = require('./helpers/data');

const no_rm = generateNoRM(lastId);
buildPagination(params)

Bangun limit/offset/search dari query params.

Masalah yang dipecahkan: Pagination query sering diulang di banyak route. Helper ini menstandarkan page/limit/offset/search.

Contoh kasus:

  • page=2, limit=10, search="dewi" → offset 10.

Contoh penggunaan:

const { buildPagination } = require('./helpers/data');

const { page, limit, offset, search } = buildPagination(req.query);
formatResponse(res, status, data, message)

Response API standar { success, data, message }.

Masalah yang dipecahkan: Format response API tidak konsisten antar route. Helper ini menyamakan struktur.

Contoh kasus:

  • status 200 → { success: true, data, message }.
  • status 400 → { success: false, data: null, message }.

Contoh penggunaan:

const { formatResponse } = require('./helpers/data');

formatResponse(res, 200, { id: 1 }, 'OK');
auditLog(db, userId, aksi, entitas, entitasId, detail)

Catat audit trail ke tabel audit_logs.

Masalah yang dipecahkan: Tidak ada jejak siapa melakukan apa dan kapan. Audit log membantu troubleshooting dan kepatuhan.

Contoh kasus:

  • Saat pasien baru dibuat, catat CREATE patients.
  • Saat kunjungan diperiksa, catat UPDATE encounters.

Contoh penggunaan:

const { auditLog } = require('./helpers/audit');

auditLog(db, req.session.user.id, 'CREATE', 'patients', info.lastInsertRowid, { no_rm });

// Contoh lain
auditLog(db, req.session.user.id, 'UPDATE', 'encounters', id, { status: 'Selesai' });

Contoh Koding

const { validasiNIK } = require('./helpers/validasi');
const { hitungUmur, formatTanggalIndo } = require('./helpers/format');
const { maskingNIK, cekRole } = require('./helpers/keamanan');
const { generateNoRM, buildPagination } = require('./helpers/data');
const { auditLog } = require('./helpers/audit');

console.log(validasiNIK('3507123456780001')); // true
console.log(hitungUmur('1995-05-14')); // { tahun, bulan }
console.log(formatTanggalIndo('1995-05-14')); // "14 Mei 1995"
console.log(maskingNIK('3507123456780001')); // "3507************"
console.log(cekRole({ role: 'admin' }, ['admin','dokter'])); // true
console.log(generateNoRM(2)); // "RM-000103"
auditLog(db, req.session.user.id, 'CREATE', 'patients', 1, { no_rm: 'RM-000103' });

Deployment

  • Set PORT, SESSION_SECRET, APP_NAME di .env.
  • Jalankan node database/migrate.js untuk migrasi.
  • Gunakan reverse proxy (Nginx) untuk production.
  • Ganti Tailwind CDN dengan build production untuk performa.
